# 开发总览

不会写代码也能做插件：把本章和对应类型章节里的「复制给 AI 的规则」整段发给 AI（Claude、ChatGPT、Cursor 等），再说清楚你想要什么，AI 就能按麦麦工坊的规则写出来。你要做的只是检查效果、打包、上传安装。

## 先选做哪一种

| 想做的事 | 选这种 | 难度 | 需要的环境 |
| --- | --- | --- | --- |
| 教小麦同学按固定方法做事，例如“按我的格式写分镜” | 技能 | 最低 | 只要一个文本编辑器 |
| 给小麦同学一个新能力，例如调用某个网站接口 | 工具插件 | 中 | 源码仓库 + Bun |
| 画布上加一个新节点，例如一个提示词模板 | 节点插件 | 中 | 源码仓库 + Bun |
| 能在「文档」面板里打开一种新文件 | 文件扩展 | 中 | 源码仓库 + Bun |

拿不准时先做技能：大部分“让 AI 按我的方式干活”的需求，一份写清楚的 SKILL.md 就够了。技能只能指挥已有能力，需要新的程序能力（联网、调接口、处理文件）时才做工具插件。

## 开发到安装的流程

1. **写**：把规则发给 AI，让它生成文件。
2. **构建**：技能不用构建；其他三种在源码仓库里运行一条构建命令，得到一个 `.js` 文件。
3. **安装**：「插件市场 › 安装插件」选择文件上传。
4. **试用**：画布里加节点、对话里让小麦同学调用，或者打开对应文件。
5. **改了再装**：同名插件只有版本号更高才会覆盖。开发调试时可在「设置 › 开发者选项 › 手动安装插件」勾选「强制安装（允许覆盖同版本或降级）」。

## 产物与安装文件

| 类型 | 构建产物 | 版本号写在哪 |
| --- | --- | --- |
| 技能 | `SKILL.md`，或包含它的 `.zip` | SKILL.md 的 `metadata.version` |
| 工具插件 | `build/tools/名称.tool.js` | `package.json` 的 `version` |
| 节点插件 | `build/nodes/名称.umd.js` | `package.json` 的 `version` |
| 文件扩展 | `build/ext/ext-名称.umd.js` | `package.json` 的 `version` |

版本号用完整的三段格式，例如 `1.0.0`、`1.0.1`。每次要正常更新，就把版本号调高。

## 开发环境（工具、节点、文件扩展）

这三种插件要在麦麦工坊的源码仓库里开发，因为它们依赖仓库里的脚手架包（`workspace:*`）。准备步骤：

1. 安装 [Bun](https://bun.sh)。
2. 取得麦麦工坊源码仓库，在仓库根目录运行 `bun install`。
3. 新插件放在 `packages/tools/`、`packages/nodes/` 或 `packages/ext/` 下，新建后重新运行一次 `bun install`。

常用命令（在仓库根目录运行）：

| 命令 | 作用 |
| --- | --- |
| `bun run dev` | 启动开发版客户端（网页 + 服务） |
| `bun run dev:plugins` | 构建全部插件并同步到开发数据目录 `data/` |
| `bun run --cwd packages/tools/名称 build` | 只构建一个插件 |

## 运行边界

- 工具插件在本机服务进程里运行，能读写工作区文件；节点和文件扩展在客户端页面里运行。
- 优先使用宿主提供的能力：工作区文件、模型、画布、FFmpeg。不要把真实 API Key 或本机数据写进源码，需要密钥就做成配置项让用户自己填。
- 插件的配置表单统一用 form-create 的 JSON 规则，下文各章都有示例。

## 复制给 AI 的规则（通用）

```text
你在为「麦麦工坊」桌面客户端开发插件。请严格遵守：
1. 使用 TypeScript、ES Modules；Vue 组件使用 Vue 3 <script setup lang="ts">，.vue 文件顺序为 <template> → <script> → <style>。
2. 自己命名的文件、文件夹、变量、函数、CSS 类名一律用小驼峰（例如 noteNode、echoTool、panelHeader），不用短横线、下划线、大驼峰或全大写。
3. 第三方组件模板标签用短横线（例如 <el-input />），组件属性名用小驼峰（例如 :showPassword）。
4. 不写测试文件，不新增依赖，除非我明确要求。
5. 不在代码里写死任何 API Key、账号或本机路径；需要密钥就做成插件配置项（form-create JSON 规则）。
6. 只实现我要求的功能，不自行加示例数据或多余功能。
7. 版本号写在 package.json 的 version，使用完整 SemVer（例如 1.0.0）。
8. 输出完整的每个文件内容和文件路径，并告诉我在仓库根目录运行哪条构建命令。
```

把通用规则和对应类型章节的规则一起发给 AI，然后描述你的需求。
